
• 1. Harden terminal session management (backend first)

- Create a global sessions = {} dict keyed by request.sid.
- On start_terminal: open PTY, spawn process, store {master_fd, process, thread, started_at} in sessions[sid].
- On disconnect and terminate_terminal: kill process safely (terminate then kill fallback), close FD, delete session entry.
- Add event emits: terminal_started, terminal_error, terminal_closed.

2. Add terminal resize and reliability events

- Add terminal_resize socket event and call ioctl(TIOCSWINSZ) on PTY.
- Add backend guard checks so terminal_input is ignored if no live session.
- Emit structured errors ({code, message}) so frontend can show clear status.

3. Create preset config system

- Add backend/config/presets.json with initial presets.
- Define schema fields: id, name, description, command, args, cwd, env, category.
- Implement load/save helpers with file lock and validation before write.

4. Build preset CRUD APIs

- GET /api/presets returns all presets.
- POST /api/presets creates/updates one preset after schema validation.
- DELETE /api/presets/<id> removes preset.
- Return consistent responses: {status, data|error}.

5. Add secure preset launch API

- POST /api/presets/<id>/launch accepts runtime params.
- Expand template placeholders safely (no raw shell concat).
- Optionally enforce command allowlist.
- Return launch payload for socket start (or start directly server-side).

6. Implement frontend terminal modes

- Add “Native Shell” button to launch /bin/bash.
- Add “Preset Launch” panel with searchable preset list.
- On preset click: show editable command preview before run.
- Keep terminal editable after launch (user can continue typing freely).

7. Add preset editor UI

- Add modal/form for create/edit/delete preset.
- Validate required fields client-side before submit.
- Wire to preset APIs and refresh list after save/delete.

8. Add command reset + quick insert UX

- Add “Reset to preset default” action to refill command input.
- Keep cheat commands as clickable inserts (do not auto-run unless user confirms).
- Add visual session badge: ACTIVE, DISCONNECTED, ERROR.

9. Refactor frontend for maintainability

- Split current inline script into modules:
- api.js (HTTP/socket calls)
- terminal.js (xterm lifecycle)
- presets.js (preset UI/state)
- app.js (bootstrap/events)
- Keep existing design/theme; avoid introducing heavy dependencies.

10. Validate before shipping

- Run: lint/type checks (if configured), then backend smoke tests.
- Manual test matrix:
- open/close terminal repeatedly
- disconnect/reconnect browser
- run preset + edit command + execute
- invalid preset payload handling
- Update README with preset schema, launch flow, and troubleshooting.
