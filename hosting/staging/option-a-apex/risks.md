# Risks — Layout A (apex)

Apex is the highest-risk option because `nullai.tech` is already live with an existing homepage (including `/swarm`); overwriting the document root with `public/` destroys that content and produces SEO/identity churn if canonical URLs or OG tags still point at `zoth.nealfrazier.tech`, and any leaked operator surface (stale `/api`, dashboard links, or bundled secrets) becomes public the moment the DNS cutover flips—there is no rollback until a backup of the old root is restored, and search engines will reindex the new title and brand under the same hostname, which is exactly the desired end state but only after every canonical, JSON-LD, OG, and sitemap reference has been updated in the source files, making this layout strictly worse than B or C until those in-place HTML edits are explicitly requested and verified.
